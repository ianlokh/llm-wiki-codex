# Local Wiki Ingestion

Before editing, read `AGENTS.md`, `DOMAIN.md`, `templates/README.md`, `templates/concept.md`, `templates/entity.md`, and `templates/source.md`. Prefer running under the `wiki-ingest` profile (workspace-write, no network). Every page you write opens with a YAML frontmatter block — take its keys from `templates/README.md` and its allowed values (tags, confidence, `entity_type`, `origin_kind`, enabled optional fields, `link_style`) from `DOMAIN.md`.

1. Accept only material supplied directly in the current task or stored in `inbox/`. Do not fetch URLs or look for extra information.
2. Record provenance first: create or update a source record in `wiki/sources/` (from `templates/source.md`) with a lowercase, hyphenated filename. **Break the input apart before you summarize** — list the input's separate, meaningful claims and record each as its own bullet under `## What it asserts`, keeping the specifics that make it answerable (names, dates, quantities, who said it) and its status (reported/rumored/confirmed/fact). Leave out filler (ads, navigation, markup, tracking). State the input's size and shape in `## Origin` (e.g. "a 17-story news digest", "a 200-row dataset") and its gaps in `## Limitations`. The source record is the faithful record of the input — never reduce a multi-item input to topic labels. Fill the source frontmatter (`type: source`, `origin_kind`, `source_format`, `tags`, `item_count`, `claim_count`, `ingested`, `ingested_by`); set `item_count` to the number of separate items in the input and `claim_count` to the number of bullets you record under `## What it asserts`.
3. Decide the page's kind. A **concept** explains how an idea, method, or topic works → `wiki/concepts/` from `templates/concept.md`. An **entity** describes one specific named thing — a person, organization, product, tool, model, or place → `wiki/entities/` from `templates/entity.md`. When unsure, put topics in `concepts/` and named things that could carry a fact-box in `entities/`. When the input bundles many separate items (a digest, feed, multi-finding report, or dataset), do **not** create one catch-all page: give each item big enough to fill the schema its own concept or entity page, and leave smaller items as citable claims in the source record.
4. Search the chosen folder for an existing page. Update it only when the request allows that; otherwise create one lowercase, hyphenated Markdown file there from the matching template.
5. Fill the page frontmatter per `templates/README.md` and `DOMAIN.md`: `title`, `type` (`concept`/`entity`), `entity_type` for entities, `tags` chosen from the registry (reuse first; add a new tag to `DOMAIN.md` in the same ingest if nothing fits), `confidence` from the rubric (the least-certain claim the page relies on), `created`/`updated` as today's ISO date, and a one-line `summary`; add `aliases`/`related` (bare slugs) when verified. Then keep the required headings (`## Summary`, `## Key ideas`, `## Sources`, `## Related` — the same for both page types). Write a claim only when the recorded source supports it; flag uncertainty and contradictions rather than settling them from memory.
6. In `## Sources`, link each claim to its `wiki/sources/` record with a relative link. In `## Related`, add only verified relative links to other published concept or entity pages.
7. Update `wiki/index.md` last, one page at a time, so the page can be found without clashing with another ingest running at the same time.

Before handing off, check coverage: confirm that every meaningful item you found in the input appears as a claim in a source record, and report the count found versus the count recorded. Then report the changed paths, the provenance recorded in `wiki/sources/`, and every unresolved gap; optionally write this to `reports/ingest-YYYY-MM-DD.md`. Ask for linting; do not answer an end-user query yourself.
